Key Quest: make a platformer game

Python turtle. Jump on platforms. Get the key. Open the door.
Python Turtle picture guides

What you will make

A simple game. A blue square runs and jumps across green platforms, picks up a gold key, and opens a red door.

We built the world for you. You write the controls, the jumping, the key and the door. That is about 30 lines of your own code.

How to play your game: arrow keys to move, space bar or Up arrow to jump.

Start: Part 1

What you need

  • Python with IDLE. It is on the school computers. At home, see Python at Home.
  • About 44 minutes for the main game (Parts 1 to 5). Parts 6 and 7 are bonus.
  • You do not need to know any Python before you start. Each part explains every new idea.
  • You type your own code. Copy and paste is switched off on the code you must type.

The world we built for you

  • YOU are the blue square.
  • The green platforms are things you can stand on.
  • The gold key is at the top right.
  • The red door is at the bottom right. It needs the key.
  • The gold coins are on the way up. They are a bonus.
  • The game already has gravity: you fall down unless you are standing on something.

For the teacher

  • Design: pupils get a starter file with the world and the game engine (gravity, landing on platforms, a game loop) already written. They type only the controls, the jump, the key and the door, under marked PART lines. It uses the turtle module in IDLE, so nothing extra needs installing.
  • Tested: every picture is drawn by running the real code. A bot plays the finished game through the real turtle engine and completes it (all three coins, the key, the door) at four different key-repeat speeds.
  • New ideas beyond Programming 1: def (functions), if and else, True and False, and a for loop over a list in the bonus part. Each is introduced in a green "New idea" box.
  • Typing only works as in the picture guides: the lines to type cannot be selected or copied. The starter file itself can be downloaded or copied, because it is not something to type.
  • Common trap: pupils must click on the game window before the keys work. It is in every error panel.
  • Timings are estimates. Parts 1 to 5 fit a lesson for most classes. Parts 6 and 7 are extension.
  • Not tested: by pupils in IDLE on the school computers, or on a Mac. Key repeat feels different on different computers.
